# 003-summarize — 3行に畳む（日→日 / 英→日）

**測るもの: 行数を守り、日本語で書き、原文に無い数字を出さず、要点を落とさないか。**

| 項目 | 値 |
|---|---|
| ケース数 | 2（日本語1本・英語1本） |
| 1ケースの合否 | 下表の全部を通ること |
| 段の通過条件 | 全ケース × 全実行（既定3回）が合格 |
| 正解 | **持たない**（必須要素 `must-cover.txt`）。**未検品** — `../REVIEW.md` |

| 見るもの | judge |
|---|---|
| 空でない | `judge_nonempty` |
| 3行以内 | `judge_max_lines` |
| 日本語である | `judge_japanese` |
| 要点が残っている | `judge_covers_all` |
| **原文の書き写しでない** | `judge_not_echo` |
| 前置き・箇条書きが無い | `judge_forbidden` |
| **数字を捏造していない** | `judge_numbers_subset` |

## 正解を持たない理由

**要約に単一の正解は無い。** 正解の3行を置くと、**モデルがそれより良い要約を書いたときに落とす**。
旧 `001-scout-filter` を撤去したのはこの失敗が原因で、上位モデルほど落ちるという逆転が起きた。

代わりに **下限だけ決める**。`must-cover.txt` は「妥当な要約なら必ず残る事実」。
上限は決めない。

## 英語→日本語を1本入れてある理由

以前の測定で、判定の大半を**英語の技術記事1本**が担っていたことがあった
（偶然そうなっていた）。**偶然の偏りを、意図した軸に変えてある。**
翻訳しながら畳む段は、日→日 より一段重い。
