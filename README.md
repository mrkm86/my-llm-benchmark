# my-llm-benchmark

**「MMLU 78.2」ではなく「朝刊は組めない。要約までなら3回中3回通る。1本4.2秒」と言うための物差し。**

世間の LLM ベンチマークは作法が確立している一方で、スコアを見ても
「自分の仕事の何ができるようになるのか」が分からない。単位が抽象だから。

このリポは、**作法は世間のベンチと同じにしたまま、問題だけを自分の現場の仕事に差し替える**ための
フレームワーク。ベンチマークそのものではない。

```
問題（シナリオ） = あなたが持つ。このリポの外に置く
測り方（ハーネス） = このリポ
```

## 出したい答えの形

結果は**3つだけ**。全部、日常の単位で読める。

| 指標 | 例 |
|---|---|
| **どの仕事まで通るか** | 「003 の要約までは通る。004 の朝刊は無理」 |
| **何回に何回通るか** | 「3回中3回」／「3回中2回」（確率にしない） |
| **1本あたり何秒 / クラウドならいくら** | 「朝刊1本 3分12秒。クラウドなら同じ量で月◯円」 |

## 使い方

```bash
bash bench.sh --scenarios /path/to/your/scenarios --model granite4.2:8b --runs 3 --weight-gb 5.3
```

まず配線確認（同梱の唯一のシナリオ）:

```bash
bash bench.sh --scenarios ./examples --model granite4.2:3b --runs 1 --weight-gb 2.2
```

アンカー（いまその仕事を回しているクラウドモデル）を**先に**通す:

```bash
bash bench.sh --scenarios /path/to/your/scenarios --model anchor:claude-opus-5 --runs 3 --skip-preflight
```

`--help` で全オプション。

## ディレクトリ規約

```
my-llm-benchmark/
├── bench.sh                1モデルにシナリオ一式を流す
├── lib/
│   ├── invoke.sh           モデルを呼ぶ唯一の口（ollama / anchor）
│   ├── judge.sh            失格条件の当て込み
│   ├── preflight.sh        メモリの三段ガード
│   ├── report.sh           実行条件つきレポート
│   └── common.sh
├── templates/scenario/     新しい段の雛形。コピーして使う
├── examples/000-hello/     公開されるシナリオはこれだけ（配線確認用）
└── docs/method.md          作法（3回・アンカー・失格条件・版の切り方）
```

### シナリオ側の規約

`--scenarios` に渡すディレクトリは、`NNN-name/` を**要求の軽い順**に並べたもの。

```
scenarios/
├── 001-<いちばん軽い仕事>/
│   ├── README.md               この段が要求するもの / 判定方法 / 合格ライン / 既知の限界
│   ├── run-test.sh             1実行ぶんの処理。exit 0/1/2/3
│   ├── system.txt              固定の system prompt（任意）
│   ├── cases/                  入力（実物から採って fixture 化）
│   │   └── FIXTURE.md          置換方針と置換ログ
│   ├── expected/               正解（機械照合する段だけ）
│   ├── disqualifiers.md        失格条件（生成物の段）
│   └── disqualifiers.patterns  上のうち機械判定するもの
└── 002-.../
```

`run-test.sh` の終了コード:

| code | 意味 |
|---|---|
| 0 | 合格 |
| 1 | 失格（失格条件に当たった） |
| 2 | **判断できない** — 人を呼ぶ |
| 3 | **測れなかった** — 落ちたのではない |

`2` と `3` を `1` に丸めないこと。**「無理だった」と「試せなかった」は別のこと。**

新しい段は `templates/scenario/` をコピーして作る。

## テスト

```
./tests/run.sh
```

シナリオはこのリポの外にあるので、ここでテストできるのは**判定そのもの**
— 当たるべきときに当たるか、当たらないべきときに黙っているか。
ネットワークもモデルも ollama も要らない。

**モデル出力を模した fixture は、すべて末尾改行なし。** 実際のモデル出力がそうだからで、
このファイルが書かれた原因のバグがまさにそこだった（`grep -c` が終端していない最終行を
数えず、3段落の回答が2行と数えられて min 3 を落ちていた）。

bash / zsh のどちらで起動しても通る（`bash tests/run.sh` / `zsh tests/run.sh` / 直接実行の3経路で確認）。

⚠️ **数える道具は、環境で答えが変わるものを避けている。** 非空行は `awk NF`（`grep -c` は
実装で割れる）、文字数は python3（`wc -m` は `LANG` 未設定でバイト数に落ちる）。
理由は `docs/method.md` の「数える道具」節。

## なぜ scenarios を外に置くのか

`bench.sh` は**シナリオの場所を知らない**。実データ（取引先名・個人名を含むケース）は
このリポに構造上入らない。`.gitignore` と注意力で守るのではなく、**分離を構造で保証する**。
`.gitignore` は忘れられるが、リポが別なら忘れようがない。

`results/` も**意図的に持たない**。モデルが変われば数字は意味を失うので、
結果は生鮮品として scratchpad に置いて捨てる。残すのは**1行のカタログと、壊れ方の現物引用**だけ
（→ `docs/method.md` 11）。

## 前提

- macOS（`vm_stat` / `sysctl vm.swapusage` を使う。メモリガードは macOS 依存）
- `bash` / `curl` / `python3`
- ローカル実行に [ollama](https://ollama.com)（起動していなければ `bench.sh` が上げる）
- アンカーに使うクラウド CLI（既定は `claude`）
